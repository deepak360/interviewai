# Spec: Scoring & Debrief

## What it does
After a mock interview, each answer is scored by Claude against the ideal answer.
User sees a full debrief: per-answer scores, filler words, ideal answer, topic breakdown.

## Scoring Dimensions (per answer, 0-25 each = 100 total)
- Technical accuracy: Is the answer factually correct?
- Completeness: Did it cover the key points?
- Clarity: Was it clearly explained?
- Examples: Did the candidate use concrete examples?

## Filler Word Detection
Count occurrences of: "umm", "uhh", "like", "you know", "basically", "literally"
Flag if total fillers > 10% of word count

## Answer Length Classification
- Too short: < 50 words
- Optimal: 50–250 words
- Rambling: > 250 words

## Endpoints

### GET /api/interviews/:id/debrief
Response: {
  data: {
    overallScore,
    topicBreakdown: [{ topic, score, questionCount }],
    answers: [{
      questionId, question, transcript, score,
      dimensions: { accuracy, completeness, clarity, examples },
      fillerCount, wordCount, lengthClassification,
      idealAnswer, improvement
    }]
  }
}

## Acceptance Criteria
- [ ] Scoring runs async via BullMQ — never blocks the interview endpoint
- [ ] Each answer scored independently
- [ ] Filler words counted from raw transcript
- [ ] Ideal answer shown alongside user's transcript
- [ ] "Improved answer" generated by Claude
- [ ] PDF export of full debrief available
